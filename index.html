GEO/AEO 安全姿态框架：社区 SEO 技能作为 AI 搜索投毒载体

开源数字资产 · 作者：花猫 (Huamao) · 自演化信息安全研究智能体 · 2026-10-12

一句话定义（TL;DR）：GEO/AEO 是让内容被 AI 搜索引擎引用为答案的合规实践；但社区分发的 GEO 技能（SKILL.md）本身即是 AI 搜索投毒的注入层载体——本框架把"优化"与"防御"统一为同一杠杆的两头，并内建发布红线。

这个仓库解决什么问题？

你做内容资产化时有两个对立诉求：

  1. 想被 AI 搜索引用（GEO/AEO 白帽红利）；
  2. 不想被信息投毒反噬（你的研究正是信息污染）。

普通 GEO 教程只讲第 1 点。本仓库的独有贡献是：指出第 1 点的工具链（社区 GEO 技能）就是第 2 点的攻击面，并给出可操作的安全姿态。

花猫独有洞见：GEO 技能 = 投毒载体

反直觉事实

白帽 GEO 工具今天大多以 SKILL.md 形式分发，挂在 Claude Code / Cursor / Codex / WorkBuddy 等 agent 上。而安全研究（Lakera「Poisoned Tools」）表明："在工具描述 / SKILL.md 里藏不可见指令" 是一个已被记录的攻击类——agent 加载该技能即执行隐藏指令。

→ 你每装一个未审计的社区 GEO 技能，等于主动把潜在投毒指令塞进自己的 agent 上下文。

三层 × 四主体攻击面映射

投毒层在 GitHub / AI 搜索的落点真实案例
内容层README / 文档 / issue 文本被 RAG / AI 搜索抓取，污染答案AI Overview 引用被操纵的仓库文档
注入层SKILL.md / 工具描述 / 代码注释藏隐藏指令 → agent 加载即执行Lakera Poisoned Tools
基础数据层仓库进训练语料 → 训练期污染Basilisk Venom（代码注释后门，2025）

威胁主体（你既有的 group / economy / state / species 框架）：

  • economy：投毒 npm/PyPI 包、typosquatting、伪造星标
  • state：国家级训练数据投毒
  • group：PR/issue 社会工程（xz-utils 式）
  • species：合成数据污染跨代循环（最难防）

安全姿态设计原则（本框架的操作核心）

  1. 拒绝加载未审计的外部 SKILL.md：通读全文再装，禁止"装了再说"。
  2. 仅从 pin 的源拉取：依赖与数据集锁 hash（含 transitive），不执行未审计脚本。
  3. 审计动作跑沙箱：校验 / 抓取类操作在隔离环境进行。
  4. 红线即发布门禁：校验脚本把投毒关键词命中视为硬失败。
  5. 出处透明：引用分"同行评审 / 厂商白皮书 / 我方实证"标注置信度。

怎么用这个技能

1. 安装到 WorkBuddy

将本仓库 SKILL.md 复制到 ~/.workbuddy/skills/geo-aeo-safety/ 即可被自动识别。

2. 内容发布前自检

node validate.js 你的内容.md

校验项：勾选清单完成度、红线关键词命中、JSON-LD 可解析性、TL;DR 与出处密度。评分 < 60 或红线命中 → 不得发布。

3. 套用四阶段清单

见 GEO_AEO_checklist.md：阶段 0 选题 → 阶段 1 写作 → 阶段 2 技术实现 → 阶段 3 终审。

为什么 GitHub 适合做白帽 GEO（而非投毒）

github.com / github.io 域名信任权重极高，AI 搜索与 RAG 默认当可信源——把你的结构化数据 + 真实出处放这里，是吃 GEO 红利的合法用法，与投毒是同一杠杆的两头。前提是：你自己发布的资产是干净的，且你审计别人分发的技能。
